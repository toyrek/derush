# Dérush — repères pour une IA qui ouvre ce dépôt

Dérush par IABAI est un logiciel de montage vidéo piloté par une IA (Claude Code ou Codex), pour macOS, Windows et Linux.
Un petit serveur Node (127.0.0.1) sert une interface sans framework ; l'IA travaille dans un dossier de montage que
Dérush prépare, avec un kit Remotion, FFmpeg et une bibliothèque de compétences. Sur Mac, l'interface s'affiche dans
une vraie app (`outils/coque-mac.swift` : une fenêtre WebKit, les menus, le Dock) ; ailleurs, dans une fenêtre de
Chrome, Edge ou Brave.

## Si on te demande d'installer Dérush

Suis **[INSTALLER.md](INSTALLER.md)** pas à pas. Ne modifie pas le code pour « faire marcher » une installation.

## Si on te demande de mettre à jour

`node derush.mjs mettre-a-jour` (ou, dans l'app : le bouton *Mettre à jour* de la petite fenêtre qui annonce une nouvelle version, ou Connexions → Version → Vérifier).

## Les règles de ce dépôt

- Tout est en **français simple** : l'interface, les messages, les commentaires, les noms de fonctions.
- **Aucune dépendance** pour le serveur et l'interface (Node 20.12+, modules standard). Les moteurs (Remotion, Whisper…)
  s'installent chez l'utilisateur, dans le dossier de Dérush, jamais dans ce dépôt.
- **Ce qui dépend du système** (chemins, raccourcis, corbeille, fenêtres, liens) est dans `lib/plateforme.mjs`, nulle part
  ailleurs : pas de `process.platform` dans le reste du code.
- **Jamais de secret** dans le dépôt ni dans un projet : les clés sont dans le dossier de Dérush (`.env.local`).
- L'IA ne reçoit que les connexions données dans « Connexions », et **ne publie rien** sans demande explicite.
  L'analyse de viralité et le plan de partage (`lib/conseil.mjs`) lancent l'IA sans aucun connecteur ni clé : elle lit,
  regarde, cherche sur le web, et écrit un fichier JSON. Rien ne se publie depuis là.
- **Un logiciel, pas une page web** : rien ne se sélectionne comme du texte (sauf les champs et les réponses de l'IA),
  pas de curseur « main », pas de menu de navigateur. La timeline ne dessine que ce qui est à l'écran (`vueTl`).
- **La coque Mac** (`outils/coque-mac.swift`) se recompile avec `swiftc` après chaque changement, pour les deux familles
  de Mac, et le résultat (`outils/coque-mac`) se range dans le dépôt : les testeurs n'ont pas Swift.
- **Le micro et la caméra, sur Mac** : l'`Info.plist` porte les deux phrases que macOS affiche (`NSMicrophoneUsageDescription`, `NSCameraUsageDescription`), et la coque accorde la demande de la page seulement si elle vient de l'adresse locale de Dérush (`requestMediaCapturePermissionFor`). Rien n'est enregistré sans un clic de la personne.
- **Codex tourne toujours dans son bac à sable** (`workspace-write`). Le rendu Remotion passe par `lib/relais.mjs`.
- **Jamais de page ouverte sans un clic** : la fenêtre native n'ouvre un site que sur un vrai clic (jamais l'adresse de Dérush), et ce qu'elle ouvre ou refuse est noté dans le journal. Les vérifications faites sans que la personne le demande (l'état de Gemini) passent par `envSansNavigateur` (`lib/plateforme.mjs`) ; `agy models` n'est relancé que si Gemini est choisi ou vérifié dans Connexions (état gardé dans `etat-gemini.json`).
- **L'app Mac « sur place » se rafraîchit au lancement** (`rafraichirApp`, `outils/construire-app.mjs`) : une mise à jour par GitHub change le programme, pas la copie de la fenêtre native rangée dans l'app ; au lancement, Dérush la remplace (renommage, nouvelle signature) si `outils/coque-mac` a changé.
- **Écrire à l'IA pendant qu'elle travaille** : Claude est lancé en `--input-format stream-json` ; un message de l'humain lui est écrit sur son entrée, il le lit au geste suivant (`--replay-user-messages` dit quand il l'a pris). Codex et Gemini ne lisent rien en route : le message part à la suite, tout seul. Ses pièces jointes partent avec lui (préparées, posées dans `contexte/`, leurs chemins ajoutés au message : `ajouterMessage`). « Après ce travail » (`apres`) garde un message pour la fin, même avec Claude : il part comme une nouvelle demande.
- **L'IA répond toujours en français** (consignes, rappel, demande) : une réponse en anglais était arrivée après une publication.
- **Le crédit API de Claude ne sert qu'au choix de la personne** (`lib/claude-api.mjs`) : jamais tout seul, jamais par défaut. Il n'est proposé que quand le forfait Claude est épuisé (au moment d'envoyer, ou dans la bulle de l'IA), pour cette demande-là ; Claude Code reçoit alors `ANTHROPIC_API_KEY`, et ce que la demande a coûté est noté et montré.
- **Le Mode Hollywood est une équipe de trois IA** (`lib/equipe.mjs`) : Gemini réalise, l'IA de « Qui monte ? » monte, ChatGPT dessine (`lib/graphiste.mjs`), chacune avec son modèle (« Ton équipe »). Quand le quota de l'une est à bout, les deux autres continuent sans rien demander : un monteur à bout passe la main à la suivante (Claude, Codex, Gemini), au départ ou en plein travail (elle reprend le même dossier, une seule fois par demande) ; jamais au crédit API de Claude tout seul. Mais il est proposé : à l'envoi, Claude à bout, la fenêtre « Ton forfait Claude est épuisé » laisse choisir entre le relais, un autre compte Claude et « Claude, avec mon crédit API » ; choisi (`creditApi` de `composerEquipe`), Claude reste le monteur de l'équipe (`monteur.credit_api`), et la phrase de l'équipe dit quand il peut l'être (`monteur.api_possible`). En mode Classique, rien de tout cela : la suite reste au choix de la personne.
- **Plusieurs comptes par IA, au clic seulement** (`lib/comptes.mjs`) : ChatGPT (Codex) et Claude. Un autre compte a son dossier dans celui de Dérush (`comptes/<ia>/<id>/`), donné à l'IA par `CODEX_HOME` ou `CLAUDE_CONFIG_DIR` ; le principal est celui de l'ordinateur. Dérush ne change JAMAIS de compte tout seul : quand celui qui travaille est à bout, il propose « Continuer avec « … » » (bulle, ou fenêtre à l'envoi) et la personne choisit ; le relais du Mode Hollywood passe d'une IA à l'autre, jamais d'un compte à l'autre (les conditions d'OpenAI et d'Anthropic interdisent de contourner leurs limites en faisant tourner des comptes). Seul un compte connecté peut être choisi. Une conversation appartient au compte qui l'a commencée (`comptes_sessions` de l'état) : avec un autre compte, l'IA repart du dossier et du résumé. Les connecteurs de Codex à couper sont lus dans le `config.toml` de CE compte (couper un connecteur qu'il n'a pas : « invalid transport », Codex ne démarre pas). Rien de personnel n'est gardé : un nom donné par la personne ; l'empreinte qui repère deux fois le même compte (`etatCompte`) reste en mémoire. Gemini n'en a pas (agy garde un seul compte Google dans `~/.gemini`).
- **Les quotas des IA se lisent sans rien consommer** (`lib/quotas.mjs`) : Codex par son app-server, Claude par ce qu'il annonce pendant son travail (sa vérification à la demande, sur un clic, est une toute petite demande). Rien de personnel n'est gardé : ni identifiant de compte, ni clé.
- **Les outils de son d'autres auteurs** (Real SFX, Earshot) ne sont pas livrés ici : `lib/sons.mjs` les télécharge chez
  l'utilisateur, à une version précise qui a été relue (`VERSIONS_SONS`). Avant d'en changer, relis leur code.
  `earshot llm` reste coupé : il envoie le son à Google.

| `lib/medias.mjs` (version de montage) | Ce que l'IA reçoit d'un rush : le fichier tel quel s'il se lit par WebCodecs (H.264, HEVC, VP9, AV1 en 4:2:0), sinon une version H.264 faite une fois en tâche de fond (ProRes, MXF, 4:2:2, HDR, Log converti, vidéo tournée) ; posé dans le pack par un clone (`cloner`, `lib/plateforme.mjs` : `cp -c` sur Mac), jamais réencodé à chaque demande |

| `lib/son.mjs`, `outils/derush-son.mjs`, `outils/echo.py` | La voix claire (« auto » par défaut : `fondSonore` mesure l'écart entre la voix et le fond, et une voix déjà nettoyée — 36 dB ou plus — passe en « léger », sans débruitage, sinon « normal » ; FFmpeg, ou DeepFilterNet s'il est dans `moteurs/deepfilter/` du dossier de Dérush : binaire officiel 0.5.6, limité à 12 dB d'atténuation en « doux », 30 en « normal », sans limite en « fort » (`ATTENUATION_DFN` : mesuré le 14 nov. 2026, 13 à 21 dB de souffle en moins que FFmpeg sur une voix bruitée exprès, la voix aussi proche de l'originale), un son très fort baissé avant lui (il écrit en 16 bits), aucun retard à retirer (`-D`) ; écho réduit par WPE dans le Python de Dérush ; décalage des filtres mesuré et retiré), la brillance de la voix (`brillance`, `avisBrillance` : aigus 2,5–8 kHz contre bas médium, nette entre −15 et −11 dB, sourde sous −16), le mixage (la musique mesurée et posée 15 dB sous la voix mesurée, qui remonte dans les silences ; effets d'une piste : étouffer, couper, volume ; remplissage fini et durée imposée à FFmpeg, sinon il écrit parfois sans fin ; −14 LUFS) et les mesures ; la commande `derush-son` est donnée à l'IA |
| `lib/controle.mjs`, `outils/derush-controle.mjs`, `outils/controle.py` | Le contrôle des textes à l'écran : Apple Vision lit chaque image (3 par seconde), le correcteur du Mac dit si un mot existe ; seuls les mots du montage sont jugés (transcription, sous-titres, table de montage, textes du kit), pas le texte filmé : les rushes du pack sont lus eux aussi (une image par seconde, cache `rendu/controle/.texte-filme.json`) et une ligne qui s'y trouve déjà n'est jamais jugée. Mots collés (une lecture seule est relue sur deux images voisines), texte coupé au bord (immobile sur deux images), texte sous l'interface du réseau ; planche des images en cause. Sur les mêmes images, l'accroche écrite (`accrocheEcrite` : le plus grand texte du montage des 2 premières secondes, discrète sous 7 % de la hauteur). La commande `derush-controle` (aide : `--help`) juge aussi la voix (brillance) et le rythme (`lib/rythme.mjs`) ; elle est donnée à l'IA, et Dérush refait ces contrôles sur chaque vidéo livrée (lignes « Textes à l'écran », « Accroche », « Voix », « Rythme »). Elle écrit aussi la planche de toute la vidéo (`plancheEntiere` : une image par seconde, 48 cases au plus ; `second_regard` de sa réponse) : le second regard de l'IA, qui se note sur 10 et corrige jusqu'à 8 (deux passes au plus). |
| `lib/rythme.mjs` | Le rythme d'une vidéo finie : Whisper la réécoute (`transcrire.py`), puis `jugerRythme` signale un début qui tarde, les pauses de plus de 0,7 s, les hésitations, les redites (les mêmes 4 mots deux fois en 25 s, prolongées des deux côtés) et les mots repris (« le le », pas « nous nous » ni « Salut. Salut, ») ; le débit et le temps qu'on pourrait gagner. Tout est « à regarder » : l'IA tranche |
| `lib/espaces.mjs` | Les espaces de travail, « Pour qui ? » : **Moi**, chaque **client**, et **Personne** (`espaces/espaces.json` du dossier de Dérush). Chacun a son métier (`METIERS` : chroniques, vlog, documentaire… ; deviné d'après le profil, confirmé par la personne), son kit de marque (ton, public, interdits, mentions, couleurs, polices, logo) et son carnet. Un projet porte `espace` dans `derush.json` (sans champ : Moi ; espace retiré : Personne). L'IA d'un projet client reçoit `contexte/espace/ESPACE.md` (sa marque) et **jamais** le profil, le carnet ni la recette de Moi ; un projet Personne ne reçoit et n'apprend rien. C'est la règle de l'utilisateur : un montage pour une entreprise ne doit pas hériter du style perso du monteur |
| `lib/modeles-ia.mjs` | Le sélecteur d'IA en direct : le catalogue de Codex (`codex debug models` : les modèles visibles pour le compte ChatGPT et leurs vitesses, « Fast », « Ultrafast »), les familles de Gemini (`agy models`), la liste de Claude (celle de Dérush). Dérush tient à jour, dans son propre dossier, le Codex qu'il lance (npm, toutes les 6 heures au plus ; jamais celui installé ailleurs) : un nouveau modèle d'OpenAI n'apparaît qu'avec un Codex récent. Revérifié en fond à l'ouverture du sélecteur ou de Connexions (au plus une fois par heure). « Nouveau » : un modèle vu depuis moins de 7 jours ; à la toute première vérification, ce qu'apporte la mise à jour de Codex. ## La page d'accueil du dépôt

`README.md` est la page que voient les nouveaux venus : courte, illustrée, avec le message à coller à leur IA (le même texte est dans `docs/message-d-installation.txt`). Ses images sont dans `docs/images/` : les dessins (bannière, étapes, modes) sont des pages HTML aux couleurs du logiciel photographiées par Chrome, les captures viennent de `outils/essai-interface.mjs` avec `DERUSH_ESSAI_ECHELLE=2`, sur des projets de démonstration dessinés (aucune image prise ailleurs, aucun nom de personne, aucun chemin de dossier). L'historique des versions est dans `docs/NOUVEAUTES.md`.

Le trailer de lancement est en haut de la page : un aperçu animé (`.github/medias/trailer-derush-apercu.gif`) et un lien qui télécharge le film entier (`.github/medias/trailer-derush.mp4`, en 720p ; GitHub ne lit pas une vidéo du dépôt dans la page, d'où le lien en `?raw=true`). Ces deux fichiers sont dans `.github/` et non dans `docs/`, pour ne pas partir dans l'app (qui embarque `docs/`). Les originaux en pleine qualité, horizontal et vertical, ne sont pas dans le dépôt.

## Publier une version

1. Monte le numéro dans `lib/commun.mjs` (`VERSION`) et dans `package.json`.
2. Ajoute en tête de `docs/NOUVEAUTES.md` un paragraphe qui commence par « `**10.5 — Son titre.**` » suivi d'une première phrase courte : c'est exactement ce que la petite fenêtre des mises à jour affiche chez les gens (le titre en gras, puis cette phrase).
3. Relance les essais, cherche les secrets et les chemins personnels, puis `git commit` et `git push origin main`.

Chez les personnes qui ont Dérush, l'annonce apparaît d'elle-même (au lancement, ou dans les six heures) dès que le numéro publié est plus grand que le leur. Un changement sans nouveau numéro (une faute corrigée dans la page du dépôt) ne dérange personne : il s'installe avec la version suivante, ou par Connexions → Version.

## Essayer sans rien casser

Un serveur d'essai, sur une bibliothèque à part et sans ouvrir de fenêtre :

```bash
DERUSH_BIBLIOTHEQUE=/chemin/vers/un/dossier/d-essai DERUSH_SANS_NAVIGATEUR=1 node derush.mjs --port 4334
```

`outils/essai-interface.mjs` pilote ensuite l'interface sans fenêtre, dans Chrome (voir son en-tête).

Ajoute `DERUSH_SUPPORT=/chemin/vers/un/dossier/d-essai` pour ne toucher ni aux réglages, ni aux projets récents, ni aux commandes de la vraie installation (relie-y `moteurs`, `competences`, `node_modules` par des liens pour ne rien retélécharger). **Un clic sur « Envoyer » dans un essai lance la vraie IA choisie par la personne, à son niveau de qualité** : dans un essai d'interface, force l'assistant (`moteur`) dans la requête, ou sers-toi de la commande simulée `outils/faux-agy.mjs` (voir son en-tête) avec `DERUSH_AGY`.

`node outils/essai-comptes.mjs` rejoue les 48 essais de plusieurs comptes (de fausses commandes claude et codex, un dossier personnel d'essai, jamais un navigateur) : un compte ajouté et son dossier, la connexion avec ce dossier et son lien gardé, le même compte deux fois repéré, l'état de l'IA qui suit le compte choisi, les connecteurs de Codex lus dans le bon dossier, les quotas de chaque compte, les routes (un compte pas connecté ne se choisit pas, « Retirer » déconnecte et efface), et le crédit restant du crédit API. `essai-claude` vérifie en plus le lancement avec un autre compte (Claude par `CLAUDE_CONFIG_DIR`, Codex par `CODEX_HOME` et ses connecteurs à lui), la conversation jamais reprise d'un compte à l'autre, et un forfait à bout noté pour ce compte seul, sans changer de compte.

`node outils/essai-styles.mjs` rejoue les 20 essais des styles vidéo et du Motion.md : chaque style a sa recette et l'inverse, aucune recette ne parle des outils d'OpenMotion ni ne renvoie à la vidéo d'un autre créateur, chacune dit sa provenance et sa licence, l'index les liste toutes ; « Style : … » retrouve la bonne recette ; un Motion.md est reconnu par son nom ou son contenu. `essai-claude` vérifie en plus la consigne d'un style choisi, et celle d'un Motion.md joint (Classique, et Hollywood : REFERENCE.md).

`node outils/essai-effaceur.mjs` rejoue les 8 essais de l'effaceur (la commande et ses refus, l'installation seulement pour un projet qui a du texte incrusté, un modèle qui ne correspond pas refusé) ; avec `ESSAI_EFFACEUR_SUPPORT=<dossier de Dérush d'essai où l'effaceur est installé>`, 4 de plus sur une vraie vidéo (Apple Vision et Telea, une bande sur un passage, LaMa, le son gardé).

`node outils/essai-couleurs.mjs` rejoue les 55 essais des couleurs (les courbes Log de dix profils donnent 0,18 pour leur gris, gammes, LUT appliqués par FFmpeg à une mire S-Log3, profil proposé, étalonnage d'un plan). `node outils/essai-son.mjs` rejoue les 31 essais du son (32 avec DeepFilterNet dans le dossier de Dérush d'essai) (voix claire : durée gardée, son synchrone à 5 ms près, souffle retiré, volume ; écho ; mixage : la musique réglée d'après la voix, qui remonte dans les silences, au gain annoncé, « ducking »: false respecté ; une piste étouffée ou coupée sur un passage ; commande `derush-son`). `node outils/essai-controle.mjs` rejoue les 31 essais du contrôle des textes (vocabulaire du montage, mots collés, texte coupé, ce qui ne doit pas être signalé — dont le texte déjà filmé dans les rushes —, et sur Mac une vraie vidéo lue par Apple Vision). `node outils/essai-medias.mjs` rejoue les 37 essais des médias (ce que l'IA reçoit selon le format, versions de montage, clones sans risque pour l'original, pack en quelques secondes, mesures à l'import, étalonnage automatique). `node outils/essai-ameliorations.mjs` rejoue les 52 essais de ce qui fait monter tous les modèles comme le meilleur : l'aide des commandes, la voix claire « auto », la brillance, le rythme, l'accroche, ce qui est incrusté, le carnet (dans un dossier de Dérush d'essai), le garde-fou du disque, la note du banc, les pièces du kit et, avec `DERUSH_SUPPORT` d'essai sur Mac, un vrai détourage.

Les autres suites se lancent de la même façon, chacune dans son propre dossier temporaire (`node outils/<essai>.mjs [dossier]` ; `--help` dit seulement comment l'appeler) : `essai-serveur` (les routes et la garde de la fenêtre), `essai-projet` (derush.json), `essai-claude` (le lancement des IA), `essai-windows` (les chemins et les lignes de commande de Windows, simulés), `essai-apprentissage` (espaces, fiches, suivi des vues, recette, séries, tableau de bord), `essai-kit` (le kit média, la bibliothèque d'animations, l'échelle exacte d'« Exporter », le rôle « voix » d'une pièce jointe), `essai-hollywood` (le Mode Hollywood contre un faux Google et une fausse commande agy : la clé, le choix du modèle, un modèle débordé ou sans quota, l'index, l'avis, la commande derush-gemini et son contrôle, la voie du compte Google et le relais par la clé, le plateau du réalisateur, son découpage, « Analyser » par Gemini, Hydrogen pour monter), `essai-competences` (les compétences livrées et ajoutées), `essai-drive`, `essai-voix-off` et `essai-sequences` (Depuis mon Drive, la voix off proposée, plusieurs vidéos dans un projet), et les essais d'interface `essai-drive-interface`, `essai-voix-off-interface`, `essai-sequences-interface` (Chrome sans fenêtre, un faux Claude, jamais une vraie IA). Chacune finit par « N essais réussis sur N » : avant de publier, toutes doivent être vertes.

**Le banc d'essai** (`node outils/banc-essai.mjs <cas.json> --support <dossier d'essai>`, voir son en-tête et `outils/banc-essai.exemple.json`) : la même consigne sur les mêmes vidéos, montée par une vraie IA (« rapide » par défaut), puis notée toute seule (textes, accroche, voix, rythme, son) ; un bilan Markdown et une ligne par cas dans `historique.jsonl`, pour comparer d'une version à l'autre. Chaque cas lance la vraie IA sur le compte de la personne : Opus ou Fable au niveau Maximum seulement si elle le demande. Le banc refuse le dossier de la vraie installation.

`node outils/essai-enregistrement.mjs` rejoue les 31 essais de l'enregistrement sans micro ni caméra (FFmpeg fabrique ce qu'une fenêtre enverrait, en webm comme Chrome et en mp4 par fragments comme l'app Mac) : les morceaux dans l'ordre, les refus, une prise abandonnée, Dérush qui s'arrête en pleine prise, la marque `voix_off`. `outils/essai-interface.mjs` ouvre Chrome avec un faux micro et une fausse caméra : toute la prise s'essaie donc dans l'interface. Dans l'app Mac native, macOS pose sa question au premier vrai `getUserMedia` (personne ne peut y répondre à la place de l'utilisateur) : pour essayer le reste du chemin, remplace d'abord `MediaDevices.prototype.getUserMedia` par un flux fabriqué dans la page (un oscillateur, une toile).

L'app Mac native se pilote aussi sans la regarder : fabrique-la dans un dossier d'essai
(`node derush.mjs construire-app <dossier> --sans-raccourci`), ouvre-la avec `DERUSH_COQUE_PILOTE=<dossier>`
(`open -n … --env DERUSH_COQUE_PILOTE=…`), puis pose dans ce dossier un fichier `commande.json`
(`{"id": 1, "js": "return document.title", "capture": "/chemin/image.png"}`) : la réponse arrive dans
`reponse-1.json` (voir l'en-tête de `outils/coque-mac.swift`).
